# libusb_set_option 运行时错误修复说明

## 问题描述

启动 launch 文件时出现错误：
```
symbol lookup error: /usr/lib/x86_64-linux-gnu/libpcl_io.so.1.10: undefined symbol: libusb_set_option
```

## 问题原因

1. **PCL 库需要 libusb-1.0.24+**：PCL 1.10 的 `libpcl_io.so` 使用了 `libusb_set_option` 函数，该函数在 libusb-1.0.24 中才引入
2. **系统 libusb 版本过旧**：Ubuntu 20.04 默认的 libusb-1.0.23 没有这个函数
3. **运行时库路径问题**：程序运行时优先使用了 `/opt/MVS/lib/64/libusb-1.0.so.0`（libusb-1.0.20），这个版本更旧

## 解决方案

### 方案 1：从源码编译并安装更新的 libusb-1.0（推荐）

这是最彻底的解决方案，安装 libusb-1.0.24+ 后，所有程序都能正常工作。

#### 步骤 1：安装编译依赖

```bash
sudo apt-get update
sudo apt-get install build-essential libudev-dev
```

#### 步骤 2：下载并编译 libusb-1.0.26

```bash
cd /tmp
wget https://github.com/libusb/libusb/releases/download/v1.0.26/libusb-1.0.26.tar.bz2
tar -xjf libusb-1.0.26.tar.bz2
cd libusb-1.0.26
./configure --prefix=/usr/local
make -j$(nproc)
sudo make install
```

#### 步骤 3：更新动态链接库缓存

```bash
sudo ldconfig
```

#### 步骤 4：验证安装

```bash
# 检查版本
pkg-config --modversion libusb-1.0

# 检查符号是否存在
nm -D /usr/local/lib/libusb-1.0.so.0 | grep libusb_set_option
```

应该能看到 `libusb_set_option` 符号。

#### 步骤 5：设置库路径（如果需要）

如果系统仍然优先使用旧版本，可以在 `~/.bashrc` 中添加：

```bash
export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
```

然后重新加载：
```bash
source ~/.bashrc
```

### 方案 2：使用 launch 文件中的环境变量（临时方案）

我已经在所有 launch 文件中添加了环境变量设置，优先使用系统的 libusb。但这只是临时方案，因为系统的 libusb-1.0.23 也没有 `libusb_set_option`。

**注意：** 这个方案可能仍然无法完全解决问题，因为系统的 libusb-1.0.23 也缺少该函数。

### 方案 3：降级 PCL（不推荐）

理论上可以降级 PCL 到不使用 `libusb_set_option` 的版本，但这可能影响其他功能，不推荐。

## 已修改的文件

我已经在所有 launch 文件中添加了环境变量设置：

1. `launch/capture_and_save.launch`
2. `launch/connect_by_serial_number.launch`
3. `launch/multiple_camera.launch`
4. `launch/obtain_point_cloud.launch`

添加的内容：
```xml
<env name="LD_LIBRARY_PATH" value="/usr/lib/x86_64-linux-gnu:$(env LD_LIBRARY_PATH)"/>
```

这会让系统优先使用 `/usr/lib/x86_64-linux-gnu` 中的 libusb，而不是 `/opt/MVS/lib/64` 中的旧版本。

2. **验证**：运行 `roslaunch mv3d_rgbd_ros capture_and_save.launch` 测试

## 常见问题

### Q1: 编译 libusb 时出现权限错误？

**A:** 确保使用 `sudo make install`，并且有管理员权限。

### Q2: 安装后仍然使用旧版本？

**A:** 
1. 运行 `sudo ldconfig` 更新库缓存
2. 检查 `LD_LIBRARY_PATH` 环境变量
3. 重启终端或重新登录

### Q3: 不想编译，有其他方法吗？

**A:** 可以尝试从 PPA 安装更新的 libusb（如果有的话），但通常需要从源码编译。

### Q4: 会影响其他程序吗？

**A:** 不会。安装新版本的 libusb 是向后兼容的，不会影响使用旧版本 libusb 的程序。

## 技术细节

### libusb_set_option 函数

这个函数在 libusb-1.0.24 中引入，用于设置 USB 设备的选项。PCL 1.10 使用它来配置 USB 设备的某些参数。

### 版本要求

- **PCL 1.10**：需要 libusb-1.0.24+
- **Ubuntu 20.04 默认**：libusb-1.0.23（不满足要求）
- **海康 SDK 自带**：libusb-1.0.20（不满足要求）

因此必须安装更新的 libusb 版本。

## 总结

**根本原因**：系统 libusb 版本过旧，缺少 PCL 需要的函数。

**最佳解决方案**：从源码编译并安装 libusb-1.0.26。

**临时方案**：已在 launch 文件中设置环境变量，但可能仍无法完全解决问题。

建议按照方案 1 从源码编译安装更新的 libusb，这是最可靠的解决方案。
