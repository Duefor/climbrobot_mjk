## 详细说明

### 1. PkgConfig 的作用

**PkgConfig** 是一个 CMake 模块，用于查找和配置系统库。

**为什么需要它？**
- 自动查找 libusb-1.0 库的位置
- 获取库的头文件路径和链接标志
- 跨平台兼容，适应不同 Linux 发行版

**工作原理：**
```cmake
find_package(PkgConfig REQUIRED)           # 查找 pkg-config 工具
pkg_check_modules(USB REQUIRED libusb-1.0) # 查找 libusb-1.0 库
```

这会自动设置以下变量：
- `USB_LIBRARIES` - 链接标志（如 `-lusb-1.0`）
- `USB_INCLUDE_DIRS` - 头文件路径
- `USB_LIBRARY_DIRS` - 库文件路径

### 2. libusb-1.0 的作用

**libusb-1.0** 是用户空间的 USB 库。

**为什么需要它？**
- **PCL 库依赖**：PCL 的 `libpcl_io.so` 模块在编译时已经链接了 libusb-1.0
- **解决链接错误**：如果不显式链接 libusb-1.0，会出现 `undefined reference to 'libusb_set_option'` 错误
- **USB 设备支持**：如果项目需要直接访问 USB 设备（如 3D 相机），需要 libusb-1.0

**依赖链：**
```
我们的可执行文件
  └── 链接 PCL 库 (libpcl_io.so)
      └── PCL 需要 libusb-1.0
          └── 所以我们也必须链接 libusb-1.0
```

### 3. C++ 标准升级

**修改：**
- 从 `-std=c++0x` (C++11 旧写法) 升级到 C++14
- 原因：PCL 1.10 使用了 C++14 特性

## 修改对比

### 修改前
```cmake
# 没有 PkgConfig 和 libusb-1.0
find_package(OpenCV REQUIRED)
find_package(PCL REQUIRED COMPONENTS common io)
find_package(Boost)

# C++ 标准过旧
ADD_DEFINITIONS("-std=c++0x -O3")

# 链接时缺少 libusb-1.0
target_link_libraries(hik_camera_image_pub ... ${PCL_LIBRARIES})
```

### 修改后
```cmake
# 添加 PkgConfig 和 libusb-1.0
find_package(OpenCV REQUIRED)
find_package(PCL REQUIRED COMPONENTS common io)
find_package(Boost)
find_package(PkgConfig REQUIRED)           # 新增
pkg_check_modules(USB REQUIRED libusb-1.0) # 新增

# C++ 标准升级
set(CMAKE_CXX_STANDARD 14)                 # 新增
set(CMAKE_CXX_STANDARD_REQUIRED ON)        # 新增
ADD_DEFINITIONS("-O3")

# 链接时包含 libusb-1.0
target_link_libraries(hik_camera_image_pub ... ${PCL_LIBRARIES} ${USB_LIBRARIES}) # 新增 ${USB_LIBRARIES}
```

## 安装依赖

如果系统缺少 libusb-1.0 开发包：

```bash
sudo apt-get install libusb-1.0-0-dev
```

## 常见问题

**Q: 为什么编译时需要设置 PYTHONPATH？**

A: anaconda 环境中的 empy 4.2 与 ROS noetic 不兼容，需要优先使用系统的 empy 3.3.2。

**Q: 可以不用 PkgConfig，直接链接 libusb-1.0 吗？**

A: 可以，但不推荐。直接链接需要手动指定路径，跨平台兼容性差。PkgConfig 是标准做法。

**Q: 为什么所有可执行文件都要链接 libusb-1.0？**

A: 因为它们都链接了 PCL 库，而 PCL 库依赖 libusb-1.0。
